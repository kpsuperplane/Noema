# MacBook Air 16 GB local-model qualification

Run on 2026-07-15 on a MacBook Air `Mac17,3` with an Apple M5, 10 CPU cores,
10 GPU cores, 32 GB unified memory, and the Metal backend. Noema used its pinned
llama.cpp b10015 runtime at commit
`12127defda4f41b7679cb2477a4b0d65ee6a0c8f`, an 8,192-token context,
temperature 0, one active generation, and checkpoint prompt caching disabled.

This machine has 32 GB rather than 16 GB. The 16 GB fit result is therefore a
projection from isolated llama-server resident-set measurements, not a physical
16 GB acceptance run. The qualification tiers are:

- Recommended: peak llama-server RSS at or below 8 GiB.
- Advanced: peak RSS above 8 GiB and at or below 10 GiB.
- Not a 16 GB candidate: peak RSS above 10 GiB.

The recommended ceiling leaves at least 8 GiB for macOS, Noema, Mnemosyne, the
webview, and ordinary applications. The advanced ceiling leaves 6 GiB and is not
appropriate for default onboarding.

## Decision

Recommend **NVIDIA Nemotron 3 Nano 4B Q4_K_M** as the 16 GB default candidate.
It passed all 11 Noema contracts in three independent qualification workers,
then passed all 11 again during a resource soak. Those qualification runs
peaked at 3.37 GiB RSS, loaded in 0.61-0.62 seconds, and had 7.14-8.67-second
median case latency. The artifact is a 2.84 GB download from NVIDIA's pinned
GGUF repository.

The soak calibrated a near-context request to 6,517 observed input tokens. It
completed in 16.36 seconds, all 20 subsequent distinct turns completed, and
post-turn RSS was flat at 3,470,196,736 bytes. Peak RSS across the entire soak
worker remained 3.37 GiB.

Promotion into the bundled recommendation catalog should still include a
physical 16 GB launch test and product/legal review of the
`NVIDIA-Nemotron-Open-Model-License`. The measured runtime margin is ample, but
this snapshot does not silently replace Ternary Bonsai in the catalog.

## Noema changes that improved qualification

The winning result depends on production improvements, not candidate-specific
fixture hints:

- The reviewer prompt states verdict semantics before task data, marks task data
  as evidence rather than instructions, and places the executor result next to
  the final review action. Nemotron moved from 10/11 to 11/11 after this change.
- The progress-audit parser accepts exactly one whole-response JSON code fence
  while preserving the strict typed payload. The eval grader now uses that same
  production parser, which removed parser drift and made Gemma 4 12B's valid
  result score correctly.
- Tool continuations now say not to repeat a successful call whose result already
  completes the request. Web summaries delimit untrusted page content and forbid
  obeying or transforming embedded instructions. Exact literal requests override
  the casual lowercase personality rule.
- The runtime passes `--cache-ram 0`. Pinned llama.cpp otherwise defaults to an
  8 GiB checkpoint cache according to the
  [pinned server documentation](https://github.com/ggml-org/llama.cpp/blob/12127defda4f41b7679cb2477a4b0d65ee6a0c8f/tools/server/README.md#L489-L502),
  which can grow resident memory across distinct turns and invalidate a 16 GB
  fit decision.

Prompt-only emphasis did not fix Gemma E2B's memory-selection miss, so that
experiment was removed. The next architectural improvement for very small
models is retrieval-assisted memory context or a dedicated structured router,
not more duplicated wording in the primary prompt.
